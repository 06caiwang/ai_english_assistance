## 一、工程结构

三个子工程 + 一份 SQL + 一份文档。**用目录隔离，不要混在一个 Gradle 工程里**——Android 工程被 AGP 管着，塞进 Maven 或 Python 会互相干扰。

```
ai-english-study/                 # 仓库根：只放子项目目录 + 共享资源，不放任何工程的构建文件
├── android-app/                  # ① Android 工程（可单独用 Android Studio 打开这一层）
│   ├── build.gradle.kts          # 根构建脚本
│   ├── settings.gradle.kts
│   ├── gradlew / gradlew.bat / gradle/ / gradle.properties / local.properties
│   └── app/
│       └── src/main/
│           ├── java/com/example/ai_english/
│           │   ├── ui/           # 4 个 Activity + BottomSheet
│           │   ├── net/          # Retrofit Api + 拦截器
│           │   ├── model/        # 请求/响应 DTO
│           │   └── util/         # TokenStore 等
│           └── res/drawable-nodpi/   # 形象图（char_*.png）
├── spring-server/                # ② Spring Boot 业务服务 :8080（可单独用 IDEA 打开这一层）
│   ├── pom.xml
│   └── src/main/
│       ├── java/com/example/english/
│       │   ├── controller/       # 13 个对外接口
│       │   ├── service/          # 业务规则（金币、饥饿值、复习）
│       │   ├── mapper/           # MyBatis-Plus
│       │   ├── entity/  dto/  config/  common/  security/
│       └── resources/
│           └── application.yml
├── python-ai/                    # ③ Python AI 服务 :8081（独立 venv，独立依赖）
│   ├── requirements.txt
│   ├── .env.example
│   ├── app/
│   │   ├── main.py               # FastAPI 两个端点
│   │   ├── graph.py              # LangGraph 四步图
│   │   ├── chain.py              # LangChain 翻译链
│   │   ├── llm.py                # 模型工厂（有 Key 走 DeepSeek，无 Key 走 mock）
│   │   ├── parsing.py            # JSON 清洗
│   │   └── schemas.py
│   └── tests/test_graph.py
├── db/                           # 共享：建表与种子数据
│   ├── schema.sql                # 7 张表
│   ├── seed.sql                  # 200 单词 + 6 形象
│   └── gen_seed.py
├── tools/                        # 共享：冒烟脚本与素材生成
│   ├── smoke.py
│   └── gen_characters.py
├── picture/                      # 原始素材（残缺图集，仅作参考，不直接用）
├── doc/
│   ├── 英语学习App-结课作业版.md  # 方案与答辩口径
│   ├── 开发流程.md                # 本文
│   ├── AI-节点图.md               # LangGraph / LangChain 节点图
│   ├── 测试报告.md                # 测试结果与未完成项
│   └── screenshots/               # 端到端实测截图
└── .workbuddy/skills/english-app-dev/   # 项目级开发手册（给后续会话用）
```

> **为什么这样拆**：三个子项目依赖的工具链完全不同（Gradle / Maven / pip），混在根目录时
> IDE 会互相扫到对方的文件，`gradlew` 也可能把 Maven 的 `target/` 当源码目录扫描。
> 拆开后每个目录都能**单独打开、单独构建、单独交付**，三端之间只靠 HTTP 契约耦合。
> 根目录只保留共享的 `db/`、`tools/`、`doc/`。

**三条命名约定，先定死免得后面改名：**

| 对象 | 约定 | 例子 |
|---|---|---|
| 接口路径 | `/api/{模块}/{动作}`，全小写，动作用动词 | `/api/pet/feed`、`/api/characters/unlock` |
| 数据库 | 表名小写下划线单数，字段小写下划线 | `user_word`、`next_review_at` |
| Android 资源 | 形象图 `char_<name>.png`，全小写无空格 | `char_panda.png` |

| Maven | 3.x | 3.8.5 | ✅ |
| Python | 3.12 | 3.13.14 | ✅ 实测 langgraph 0.2.62 / langchain-core 0.3.29 在 3.13 下装包与运行均正常 |
| conda 环境 | `english-ai` | 不存在（只有 `RAG`） | ⚠️ 改为 `python-ai/.venv`，不污染全局 |
| MySQL | 8.0 | 8.0.43 已装并连通 | ✅ root 需密码，统一走 `MYSQL_PWD` 环境变量 |
| Android SDK | compileSdk 34 | android-34 / android-36 已装 | ✅ |
| Gradle | 8.2 | wrapper 8.2 | ✅ |
| AGP | — | 模板是 `8.2.0-rc02`（预发布） | ✅ 已改 `8.2.2` + Kotlin `1.9.22`，`assembleDebug` 出包成功 |

### 2.2 环境准备清单（照着执行）

```bash
# ① 确认 JDK17 + Maven
mvn -v                      # 输出里 Java version 应为 17.x

# ② 建 Python 虚拟环境（不用 conda，避免和已有的 RAG 环境打架）
cd python-ai && python -m venv .venv
.venv/Scripts/python.exe -m pip install -U pip
.venv/Scripts/python.exe -m pip install -r requirements.txt

# ③ 确认 Android SDK
echo $ANDROID_HOME          # 空的话用 local.properties 里的 sdk.dir
ls $HOME/AppData/Local/Android/Sdk/platforms   # 应看到 android-34
```

### 2.3 数据库账号

MySQL 的 root 密码不在代码里，统一走环境变量：

```bash
# Git Bash 里临时设（只对当前窗口有效）
export MYSQL_PWD='你的密码'
mysql -u root -e "select version();"
```

Spring 侧同理，`application.yml` 用占位符 `${MYSQL_PASSWORD:}`，**不要把密码提交进仓库**。

### 2.4 大模型 Key

- 只写在 `python-ai/.env`，且 `.env` 进 `.gitignore`；
- 仓库里只提交 `.env.example`；
- **没有 Key 也要能跑**：`python-ai/app/llm.py` 在检测不到 `DEEPSEEK_API_KEY` 时自动切到 `MockChatModel`，返回结构合法的假数据。这样断网、欠费、忘配 Key 都不影响演示主链路。

### 2.5 本机实测踩到的坑（都已解决，别再踩一遍）

| 坑 | 现象 | 处理 |
|---|---|---|
| 环境变量 `SERVER__PORT` 覆盖配置 | Spring 起在 58675 且报端口占用，`application.yml` 里的 8080 完全不生效 | 启动前 `unset SERVER__PORT`，并显式传 `--server.port=8080`（命令行参数优先级最高） |
| LangGraph 节点名与 state 键重名 | `ValueError: 'score' is already being used as a state key` | 节点改名 `grade`，state 里保留 `score` |
| pytest 读到系统里的真 Key | 断言 `source=mock` 失败（环境里存在 `DEEPSEEK_API_KEY`） | 测试里显式注入 `MockChatModel`，`source` 按实例类型判断而不是读环境变量 |
| 建表时不用反引号 | `select * from character` 语法错 | 所有 SQL 与 `@TableName` 都写成反引号包裹的 `character` |
| Windows 下 `adb shell cat /sdcard/x` 被路径转换 | 报 `No such file or directory` | 命令前加 `MSYS_NO_PATHCONV=1` |
| 模拟器截图坐标与点击坐标不一致 | 点击无效 | 先用 `adb shell uiautomator dump` 取控件 bounds，再按中心点点击 |

## 阶段 0 · 骨架跑通（第 1 天）

**目标**：三套工程各自能启动，数据库有表。**这一天禁止写业务代码**，只证明「环境通」。

### 任务

- [ ] 0.1 建库建表
  ```bash
  mysql -u root -e "CREATE DATABASE IF NOT EXISTS english_app DEFAULT CHARSET utf8mb4;"
  mysql -u root english_app < db/schema.sql
  mysql -u root english_app < db/seed.sql
  mysql -u root english_app -e "select count(*) from word; select id,name,price from \`character\`;"
  ```
  期望：`word` = 200 条，`character` = 4~6 条，其中 `price = 0` 至少 1 条。

- [ ] 0.2 Spring 骨架
  ```bash
  cd spring-server && mvn -q -DskipTests package
  mvn spring-boot:run
  curl http://127.0.0.1:8080/api/ping
  ```

- [ ] 0.3 AI 服务骨架
  ```bash
  cd python-ai && .venv/Scripts/python.exe -m uvicorn app.main:app --port 8081
  curl http://127.0.0.1:8081/health
  ```

- [ ] 0.4 Android 骨架：把 AGP 改稳定版、加 Kotlin 插件、`cd android-app && ./gradlew assembleDebug` 出 APK。

### 翻车点

1. **端口占用**：8080 常被别的服务占。`netstat -ano | findstr :8080` 查 PID 再停。
2. **MySQL 8 的 `character` 是保留字倾向**：建表和查询时统一加反引号 `` `character` ``，否则 `select * from character` 会报语法错。
3. **AGP 版本**：模板的 `8.2.0-rc02` 容易拉不到依赖，改 `8.2.2` + Kotlin `1.9.22`，Gradle 8.2 正好匹配。
4. **Android 访问本机后端的地址**：模拟器用 `10.0.2.2:8080`，真机必须用电脑局域网 IP，写死在 `BuildConfig.BASE_URL`，别散落在各处。

### 回滚点

此阶段不产出业务代码，失败就重装/重配，不需要回滚。**提交一次 `chore: 三端骨架跑通` 作为基线。**

## 阶段 1 · AI 服务（第 2–3 天）

**目标**：用 curl 就能拿到作文批改和翻译结果，且日志能证明 LangGraph 的节点是**按序、可中断**执行的。

节点图详见 `doc/AI-节点图.md`，这里只讲落地顺序。

### 任务（严格按序）

- [ ] 1.1 `llm.py`：模型工厂 + MockChatModel
  - 有 `DEEPSEEK_API_KEY` → `ChatOpenAI(base_url="https://api.deepseek.com/v1", model="deepseek-chat", timeout=10, max_retries=0)`
  - 没有 → `MockChatModel`，按 prompt 里的关键词返回不同的合法 JSON 字符串
  - **必须做 Mock**：否则没 Key 时整条链路都验证不了

- [ ] 1.2 `chain.py`：翻译链
  ```
  ChatPromptTemplate | llm | JsonOutputParser  (→ TranslationResult)
  ```
  一次模型调用，不套图。

- [ ] 1.3 `graph.py`：作文批改四步图
  - `StateGraph(EssayState)`，节点：`extract_points → check_grammar → check_structure → score → advise`
  - 评分节点之后加**条件边**：分数 < 60 或维度缺失 → 回到 `check_grammar` 重跑一次（`retry < 1` 才允许），否则 `END`
  - `MemorySaver` 做 checkpoint，graph 调用时传 `thread_id`，支持中断恢复

- [ ] 1.4 `main.py`：两个 FastAPI 端点，`/ai/essay`、`/ai/translate`，Pydantic 校验出入参

- [ ] 1.5 测试：`pytest tests/` —— **不依赖网络**，全走 Mock 模型，断言 ①四步都执行 ②返回字段齐全 ③重试分支能触发

### 验收命令

```bash
curl -s -X POST http://127.0.0.1:8081/ai/translate \
  -H "Content-Type: application/json" \
  -d '{"text":"resilient"}' | python -m json.tool

curl -s -X POST http://127.0.0.1:8081/ai/essay \
  -H "Content-Type: application/json" \
  -d '{"content":"My hometown is a small city. I love it very much."}' | python -m json.tool
```

期望：翻译返回 `{meaning, phonetic, example, pos}`；作文返回 `{score, dimensions:{grammar,structure,vocabulary}, suggestions:[...]}`，且控制台能看到 `node=extract_points` → `node=check_grammar` → … 的顺序日志。

### 翻车点

1. **超时**：`timeout=10` 要设在模型客户端上，不是设在 FastAPI 上——两处都设会出现「后端认为超时、模型还在跑」的错位。
2. **结构化输出**：DeepSeek 对 `json_object` 支持有限，提示词里必须**明确要求只输出 JSON**，并配 `JsonOutputParser` 兜底清洗 markdown 代码块。
3. **Mock 分支被忘掉**：`llm.py` 里如果只有真模型分支，答辩前一晚断网就全废。
4. **图变成链**：四个节点如果串成直线，就失去了用 LangGraph 的理由。**必须有一条条件边**，这是答辩要讲的重点。

## 阶段 2 · 业务后端（第 4–5 天）

**目标**：13 个接口全通，所有数值由后端算，客户端只显示。

### 任务

- [ ] 2.1 基础设施：`Result<T>` 统一返回、全局异常处理、JWT 工具、登录拦截器（把 `userId` 塞进 `ThreadLocal`）
- [ ] 2.2 用户模块：注册（事务写 user + pet + 默认形象）、登录、`/api/user/me`
- [ ] 2.3 单词模块：今日单词（新词 + 到期复习）、答题（金币 +exp、饥饿值 +2、复习阶段推进）
- [ ] 2.4 宠物模块：饿值现算、喂食（扣 5 金币）、形象列表/解锁/切换
- [ ] 2.5 AI 转发：`RestTemplate` 超时 10s，异常统一降级为「AI 服务暂时不可用」
- [ ] 2.6 统计：`/api/stats` 已学词数、正确率、连续天数

### 关键规则（写代码前抄进 `PetService` 和 `WordService` 的注释）

```
饥饿值：hunger = max(0, 100 - minutesSince(last_fed_at) / 20)   // 等价于每小时掉 3 点
答对：coin +1, exp +2, hunger +2（上限 100）
喂食：coin -5（不足则拒绝），hunger = 100, last_fed_at = now
复习：答对 stage+1（≤4）并按 0/1/3/7/15 天排下次；答错 stage = 0
解锁：coin -price，写 user_character；条件更新 WHERE coin >= price 防超扣
```

### 验收命令

```bash
# 注册
curl -s -X POST :8080/api/auth/register -H "Content-Type: application/json" \
  -d '{"username":"demo01","password":"demo2026","nickname":"演示"}'
# 拿 token 后依次打 /api/words/today → /api/words/answer → /api/pet
# 断言：答对后 coin +1、hunger 上升；喂食后 coin -5、hunger=100
```

### 翻车点

1. **事务漏写**：注册和形象解锁都是多表写入，方法上必须 `@Transactional`，否则会出现「有钱扣了、形象没到」。
2. **饥饿值被写进库**：只在读的时候算，别定时回写，否则重启后状态错乱。
3. **两个服务时间不一致**：计算用 Java 侧 `LocalDateTime.now()`，不要让 Python 算时间。
4. **JWT 过期时间太短**：演示时 30 分钟足够，但要留自动登录（token 存 SharedPreferences）。

## 阶段 3 · 客户端主链路（第 6–7 天）

**目标**：一个不用看数据库也能走完的闭环。

### 任务

- [ ] 3.1 `TokenStore` + OkHttp 拦截器（自动加 `Authorization`）
- [ ] 3.2 登录页：注册/登录切换、错误提示、自动登录
- [ ] 3.3 首页：宠物形象、金币、饥饿值进度条、喂食按钮
- [ ] 3.4 背单词页：单词卡 + 认识/不认识 + 进度 + 结束页
- [ ] 3.5 我的页：昵称、金币、统计三项

### 翻车点

1. **主线程网络请求**：Retrofit 回调要切主线程，简单起见统一用 `runOnUiThread` 包一层。
2. **`cleartext HTTP`**：Android 9+ 默认禁明文，`network_security_config.xml` 里放行 `10.0.2.2` 和局域网 IP。
3. **饿值不刷新**：首页 `onResume` 重新拉 `/api/pet`，否则从背单词页回来数值是旧的。
4. **形象图尺寸**：统一 256×256，`ImageView` 用 `scaleType="fitCenter"`，不要 `centerCrop`（会裁掉脚）。

## 阶段 5 · 联调与测试（第 9 天）

按 `doc/测试报告.md` 的表格逐项打勾。四类测试：

| 类型 | 怎么测 | 通过标准 |
|---|---|---|
| 单元测试 | `mvn test`、`pytest` | 饥饿值计算、复习阶段推进、四步图分支全绿 |
| 接口测试 | curl / Postman 跑 13 个接口 | 正常返回 + 参数错误返回 code≠0 + 无 token 返回 401 |
| 端到端 | 模拟器走一遍闭环 | 注册→背词→喂食→解锁形象，重开数据不丢 |

## 七、提交规范与回滚点

每完成一个阶段提交一次，commit message 用「阶段 + 结果」，出问题能整段回退。

```
chore: 阶段0 三端骨架跑通
feat(ai): 阶段1 四步图 + 翻译链 + mock 兜底
feat(server): 阶段2 13 个接口与数值规则
feat(app): 阶段3 登录/首页/背单词/我的
feat(app): 阶段4 形象解锁与切换
test: 阶段5 接口与端到端测试通过
docs: 阶段6 答辩材料与录屏
```

**五个天然回滚点**：阶段 0 后、阶段 1 后、阶段 2 后、阶段 3 后、阶段 5 后。
只要这五次提交都在，任何后期改动炸了都能退回最近可用状态——这是赶工期时最值钱的保险。
